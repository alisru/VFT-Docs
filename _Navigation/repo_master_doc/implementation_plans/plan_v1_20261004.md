# Plan v1 — Repo Master Doc (functional / non-document files)
Date: 2026-10-04 · Status: PROPOSED, nothing built yet

## Goal
One master doc, `REPO_MASTER.md`, that says:
1. The folder structure and the point of each folder.
2. What every non-document file (scripts, bats, ps1, db, js, html, json, config) is for and what it does.
3. How the pieces connect (pipelines: IO convert → index → summaries; bluesky bot; hegemony/kanon audit).
4. Which files are dead, duplicate, or scratch (flagged only, never deleted).

## What I found (root only)
- ~35 top-level folders, ~90 loose files at root.
- Loose root files are mostly: one-off scripts (`append_vft_*.py`, `cleanup_structure_v2.py`, `Move-*.ps1`), batch lists (`batch_2_*.txt`, `next_100_*.txt`, `raw_*.txt`), summary data in 5+ formats (`file_summaries.*`), launchers (`.bat`, `.pyw`, `.lnk`), and data (`hegemony_db.js`, `qqci_dictionary.js`, `index_data.json`).
- Existing partial docs: `_Navigation/folder_purpose_review.md`, `Topic_Map.md`, `reorganization_audit.md`. These cover folders, not functional files. They get read and reused, not duplicated.
- `CLAUDE.md` is an empty memories stub. It is not a master doc.
- Two near-duplicate folders: `drawing board` and `drawing_board`. Flagged only.

## Phases

### Phase 1 — Inventory (no edits to anything outside this folder)
- Walk the tree, skip `.git`, `.venv`, `__pycache__`, `node_modules`.
- Write `inventory/files_nondoc.csv`: path, ext, size, last modified, top-level folder.
- Write `inventory/folders.csv`: folder, file count by type, last modified.
- Plain `Get-ChildItem` only, no API calls.

### Phase 2 — Read each non-doc file (cheapest source first)
For each script or functional file record: purpose, inputs, outputs, who calls it, status.
Order of sources:
1. Header comment, docstring, or `argparse` help text.
2. `file_summaries.db/json` (already has summaries for many files; check coverage first).
3. Grep for who references it (`.bat` calling `.py`, etc.).
4. Open the file only if the above gives nothing.
Large data files (`.db`, `.js` data, `.json`) get described by schema/shape only, not read in full.

### Phase 3 — Group by system
Likely groups (to confirm in Phase 2):
- **IO / conversion pipeline**: `io/`, `convert_io_to_md.py`, `sync_gdrive_io.bat`, `Move-IOFiles.ps1`
- **Index + search**: `Master_Index.html`, `index_data.json`, `.agents/skills/search-index`, `update-index`
- **File summaries**: `file_summaries.*`, `vft_summarizer_v2.py`, `batch_summarize_local.py`, `Heal-Summaries.ps1`
- **Bluesky bot**: `bluesky_bot/`, `AletheiaLauncher.pyw`, `Run-*Bsky*.bat`, `Post-LiveBatch*`
- **Hegemony / Kanon / QQCI data**: `hegemony_db.js`, `qqci_dictionary.js`, `hegemony_attractor/`, `Semantic_Clusters/`
- **Git/sync**: `Push.bat`, `Sync*.bat/ps1`, `Convert-ShadowRepo.ps1`
- **Agent config**: `.agent/`, `.agents/` (skills, rules), `.claude/`, `CLAUDE.md`, `.vscode/`
- **Visualisers**: `Visualisers/`, `*_graph.html`, `*.png/gif`
- **One-offs / scratch / batch lists**: flagged "likely dead" with reasoning

### Phase 4 — Write `REPO_MASTER.md`
Sections:
1. One-paragraph purpose of the repo
2. Folder tree + one-line point per folder
3. Systems (from Phase 3), each with a file table: `file | what it does | inputs → outputs | called by | status (live / legacy / unknown / dead?)`
4. Pipelines diagram (mermaid)
5. "Flagged, not touched" list: duplicates, stale, scratch, empty stubs
6. How to keep it current (see Phase 5)

### Phase 5 — Keep it current
- Add a short rule to `.agents/AGENTS.md`: any new script gets a row in `REPO_MASTER.md`.
- Optional: a read-only checker that lists files in the inventory with no row in the master doc. Reports only, never modifies.

## Rules followed

- No AI Studio / API calls.
