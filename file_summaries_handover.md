## 2. Summary Formatting & Layout Standards

All summaries added to the database must strictly follow this exact template and set of structural rules:

```markdown
### [Filename.md] (2026-05-23)
**Path**: _VFT MD\Actualism\Consciousness\[Filename.md]
**Categories**: Plane: [Plane]; Node: [Conceptual Node Name]; Tags: [Tag1, Tag2, Tag3]
**Summary**:
[Topic 1 Name]: [Topic 1 Description]\
[Topic 2 Name]: [Topic 2 Description]\
...
[Topic N Name]: [Topic N Description]
```

> [!NOTE]
> The summary is exactly one line per topic identified in the file. The list of topics is **not strictly limited to 3**; it can scale up or down (e.g., N topics) based on the depth of the document.


### Strict Formatting Rules

1. **The Node Rule (No Simple Addresses)**:
   * **Node** values **MUST NOT** be simple address codes (e.g., `n6.2.3` or `n5.3.1`).
   * They **MUST** be human-readable, meaningful concepts (e.g. `Consciousness (Identity)`, `Philosophy (Truth)`, `Cognitive Framework`, `Internal Judgment (Justice)`).
2. **No Bold in Summary Body**:
   * Bold markings (`**` or `*`) are **forbidden** within the text of the generated summaries.
   * Only the structural keys (`**Path**:`, `**Categories**:`, `**Summary**:`) may use bold.
3. **No Bullet Items / Hyphens**:
   * Do **NOT** use list markers (`-`, `*`, or numbers) in the summary text.
   * The text must flow as standard prose topics separated by trailing backslashes.
4. **Topic Trailing Backslashes**:
   * Separate topics with standard trailing backslashes `\` at the end of the line.
   * There **must be no trailing backslash** on the very last topic of the summary.
5. **Path Format**:
   * Paths must use Windows-style backslashes (`\`) and be relative to the workspace (starting with `_VFT MD\`).
