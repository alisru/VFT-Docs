# Plan 020: Support Same-Origin and Classic WYSIWYG Iframes (CKEditor, TinyMCE, Drupal)

## Context & Problem Statement
The user provided HTML from a Drupal forum (`members.greens.org.au` with CKEditor):
```html
<textarea class="text-full wysiwyg form-control form-textarea required wysiwyg-processed" id="edit-comment-body-und-0-value" name="comment_body[und][0][value]" cols="60" rows="5" style="visibility: hidden; display: none;"></textarea>
...
<iframe src="" frameborder="0" class="cke_wysiwyg_frame cke_reset" title="Rich Text Editor, edit-comment-body-und-0-value"></iframe>
```
The user stated: "doesn't work on like this".

## Why It Failed
1. **Hidden Original Textarea**:
   CKEditor hides the underlying `<textarea>` (`display: none; visibility: hidden;`). Users type into an `<iframe>` created dynamically by CKEditor with `src=""` or `src="javascript:void(0)"`.
2. **`match_about_blank` was Missing**:
   Chrome extensions do NOT inject content scripts into `src=""` or `about:blank` iframes by default even with `"all_frames": true`, unless `"match_about_blank": true` is explicitly specified in `manifest.json`.
3. **Direct Document-Level Listener Binding on Same-Origin Iframes**:
   When CKEditor creates an iframe on the parent page, the parent script can also directly attach listeners to the iframe's `contentDocument` (`body.contentEditable = "true"`).
4. **Form Submit Sync**:
   When the user clicks the `<button type="submit" id="edit-submit">Save</button>`, CKEditor copies the HTML from the iframe into the hidden `<textarea>`. But during typing, all input events occur inside the iframe's document `body`.

## Proposed Modifications

### 1. `manifest.json`
- Add `"match_about_blank": true` to `content_scripts`.
- This tells Chrome to inject `scribe_content.js` into dynamic `about:blank` / empty-src iframes generated by WYSIWYG editors like CKEditor and TinyMCE.

### 2. `scribe_content.js`
- **Active WYSIWYG Iframe Bridge**:
  - Scan for existing and dynamically added WYSIWYG iframes (`iframe.cke_wysiwyg_frame`, `iframe[class*="wysiwyg"]`, TinyMCE iframes).
  - Attach `input`, `keyup`, and `blur` listeners directly to `iframe.contentDocument` if same-origin and accessible.
  - In `getEditableRoot`, if the target is `document.body` of an editable iframe (`body.contentEditable === 'true'`), treat it as an editable container.
  - When extracting context, if inside an iframe, reach out to `window.parent.document.title` and `window.parent.location.href` to associate the draft with the parent forum post.
- **Support CKEditor / Drupal Submit Buttons**:
  - `edit-submit`, `.form-submit`, and form submit buttons are detected and trigger instant flush.

- Validate JSON in `manifest.json`.
- Validate JS with `node -c`.
