### 3. Integrated Thinking Level Controls in Operator Console
- Added a dropdown combobox for **Thinking Level** (`combo_thinking`) directly into the grid layout of [`AletheiaLauncher.pyw`](file:///e:/Vector%20Field%20Theory/VFT%20Docs/AletheiaLauncher.pyw):
  - Location: Placed on Row 2 next to the Prioritize Outlets entry box.
  - Options: `"OFF"`, `"LOW"`, `"MEDIUM"` (default), `"HIGH"`.
- Appended `--thinking-level` value when launching the bot subprocess from the UI.
- Parsed the `--thinking-level` CLI argument inside `google_ai_studio_one_shot.py` and mapped it dynamically to the Gemini API's client-side configurations:
  - **`OFF`**: Disables thinking (`thinking_budget=0` for Gemini 2.5, thinking config omitted for Gemini 3.x).
  - **`LOW`, `MEDIUM`, `HIGH`**:
    - For Gemini 3.x models, maps to `thinking_level` string parameter (`LOW`, `MEDIUM`, `HIGH`).
    - For Gemini 2.5 models, maps to token budgets (`LOW` = 1024, `MEDIUM` = 2048, `HIGH` = 4096 tokens).

### 4. Resolved Thinking Model JSON Parsing Bug
- **Issue**: Under the new `google-genai` SDK, if `thinking_config` is enabled, the API returns the reasoning chain as a distinct part within `response.candidates[0].content.parts` (where `part.thought == True`). By default, calling `response.text` joins all parts together, prepending the model's internal thought text to the final JSON array. Because the thought process contains brackets, the JSON extractor matched brackets inside the thoughts instead of the JSON array, causing parsing failures.
- **Resolution**: Refactored response extraction in both standard Gemini and Vertex AI code paths to loop over `parts` and skip any part where `getattr(part, 'thought', False)` is `True`. This isolates the final generated JSON text from the reasoning chain, allowing seamless JSON parsing.

### 5. Integrated 6-Attractor Forces for Coordinate Recalculation
- **Issue**: The coordinates (`claim_u`, `claim_psi`, `real_u`, `real_psi`) generated by the model in the one-shot batch evaluator were "sharp" (simple integers/half-integers like `1.0` or `-0.5`). This occurred because the one-shot output JSON array structure did not return the raw 6-attractor support, oppose, and neutral `[S, O, N]` forces. Consequently, the rebuilder script (`rebuild_registries_son.py`) could not run the mathematical coordinate formulas and left the model's coarse coordinates untouched.
- **Resolution**:
  - Expanded the one-shot JSON output array format from 25 elements to 27, appending `stated_forces` (item 25) and `actual_forces` (item 26) dictionaries to the schema requested from the model.
  - Updated [`google_ai_studio_one_shot.py`](file:///e:/Vector%20Field%20Theory/VFT%20Docs/bluesky_bot/google_ai_studio_one_shot.py) to parse these two dictionaries inside `transpose_flat_to_json()` and stage them in the darkroom JSON configs.
  - This allows the registry rebuilder to dynamically recalculate the exact, fractional decimal coordinates (e.g. `-0.89`, `-0.87`) using the Separated Will and Attractor formulas, and update the posts seamlessly.
